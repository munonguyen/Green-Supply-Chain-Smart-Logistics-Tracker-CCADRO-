# CCADRO AI Coding Agent Instructions & Architectural Constraints

## 1. Architectural Mandates
- **Architecture Style**: Modular Monolith.
- **Language & Runtime**: Java 17, Spring Boot 3.3.x.
- **Frontend**: React 18, Vite, Leaflet.
- **Single Source of Truth**: PostgreSQL 16 + PostGIS 3.4.
- **Redis Role**: Ephemeral cache and live fanout only; NEVER use Redis as persistent source of truth.
- **Do NOT Introduce**: Microservices, Kafka, RabbitMQ, Kubernetes, distributed orchestration, or heavy AI/ML models that complicate the one-month academic MVP.

## 2. Package & Domain Boundary Structure
All backend code resides under `com.ccadro`:
```text
com.ccadro
├── shared       (Cross-cutting config, security, exceptions, audit - OPEN module)
├── asset        (Vehicles and drivers)
├── shipment     (Freight orders, origins, destinations, spatial geometries)
├── routing      (UC05 Green multi-criteria planning, providers, adapters)
├── tracking     (UC09/UC10 Real-time GPS stream, buffer deviation, reroute proposals)
├── carbon       (UC12/UC13 GLEC v3 carbon accounting, corridor benchmarks)
└── exception    (Unified domain exceptions - OPEN module)
```
**Spring Modulith Rules**:
- Cross-module communication must happen through service interfaces or public domain models, never direct repository queries into other modules.
- Run `mvn test -Dtest=CcadroApplicationTests#verifyModularMonolithStructure` to enforce architectural integrity.

## 3. Core Use Cases Mapping
- **UC05**: Green Multi-Criteria Route Planning (`com.ccadro.routing`)
- **UC09**: Real-time GPS Tracking & Deviation Alerting (`com.ccadro.tracking`)
- **UC10**: Dynamic Incident & Congestion Rerouting (`com.ccadro.routing` + `com.ccadro.tracking`)
- **UC12**: Post-trip Emission Calculation GLEC v3 (`com.ccadro.carbon`)
- **UC13**: Freight Corridor Carbon Benchmarking (`com.ccadro.carbon`)

## 4. Invariant Business Rules
1. **Never Hardcode Parameters**: Deviation thresholds (50m yellow, 200m red), reroute minimum benefit (10%), cooldown timers, and weights must reside in `application.yml` (`ccadro.*`) or database configurations.
2. **Provider Abstraction**: All external routing, traffic, and weather calls MUST use `RoutingProvider`, `TrafficProvider`, and `WeatherProvider` interfaces.
3. **Carbon Accounting Separation**:
   - Planning carbon is predictive estimation.
   - Post-trip accounting carbon is based on actual payload and telemetry distance.
4. **Dispatcher Human-in-the-Loop**: Reroute proposals generated by UC10 require explicit dispatcher approval (`ACCEPTED`) before modifying active trip route versions.
5. **No Schema Drift**: Always use Flyway migrations (`db/migration/V***__*.sql`). Never set `spring.jpa.hibernate.ddl-auto` to `create` or `update`.

## 5. Development & Verification Workflow
Before and after making changes:
1. Review requirements in `docs/requirements/core/`.
2. Keep all services containerized via `docker compose up -d`.
3. Run `make test` (backend unit/integration tests + frontend tests).
4. Run `make smoke` to verify end-to-end capabilities.
