# UC10: Dynamic Rerouting & Traffic Incident Adaptation

## 1. Objective
Automatically detect en-route blockers, severe congestion, or prolonged off-route deviations, evaluating alternative paths to propose an optimal dynamic detour.

## 2. Requirements & Triggers
- **ID**: `CORE-RO-010`
- **Triggers**:
  - `deviation_alert` with severity `RED`.
  - `TrafficProvider` reports `ROAD_CLOSED` or `HEAVY` delay along remaining route segments.

## 3. Algorithm Rules
- **Minimum Benefit Threshold**: Reroute is only proposed if estimated improvement $\Delta \ge 10\%$ in duration or carbon penalty avoidance.
- **Cooldown Window**: Minimum 300 seconds (5 minutes) between consecutive proposals for the same trip to prevent route thrashing.
- **Dispatcher Governance**: System creates a `reroute_proposal` with status `PENDING_DISPATCHER`. Active trip route is NOT updated until human approval.

## 4. Verification Acceptance
- Generated proposals saved in `reroute_proposal`.
- On approval, new `route_version` incremented (e.g. Version 2) and trip `active_route_version_id` updated.
